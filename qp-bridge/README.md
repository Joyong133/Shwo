# QP브릿지 — 메타퀘스트 ↔ 휴대폰 블루투스 연결

메타퀘스트와 Android 휴대폰을 **블루투스 저전력(BLE)** 으로 직접 연결해 메시지를 주고받는 앱입니다.
**Wi-Fi가 꺼져 있어도, 인터넷이 없어도** 동작합니다. 두 기기 모두 블루투스만 켜면 됩니다.

| 파일 | 설치할 기기 | 역할 |
|---|---|---|
| `release/QPBridge-Quest.apk` | 메타퀘스트 2 / Pro / 3 / 3S | 찾아서 연결하는 쪽 (BLE 중앙) |
| `release/QPBridge-Phone.apk` | Android 8.0 이상 휴대폰 | 연결을 기다리는 쪽 (BLE 광고 + GATT 서버) |

> iPhone은 APK를 설치할 수 없어 지원하지 않습니다.

## 왜 블루투스인가

| 방식 | 퀘스트 Wi-Fi 꺼짐 | 비고 |
|---|---|---|
| **블루투스 BLE** (이 앱) | ✅ 동작 | 공유기·인터넷 불필요. 10m 안팎, 텍스트·제어 신호에 충분 |
| Wi-Fi Direct / 핫스팟 | ❌ | Wi-Fi 전파가 켜져 있어야 함 |
| USB 케이블 | △ | 퀘스트-폰 직결은 USB 호스트 문제로 불안정 |

## 설치

### 휴대폰
1. `QPBridge-Phone.apk` 를 휴대폰으로 받아 엽니다.
2. "출처를 알 수 없는 앱 설치"를 허용하라고 나오면 허용합니다.

### 메타퀘스트 (사이드로드)
1. 휴대폰 **Meta Horizon 앱 → 기기 → 헤드셋 설정 → 개발자 모드 ON**
2. 퀘스트를 PC에 USB로 연결하고, 헤드셋 안에서 **"USB 디버깅 허용"** 을 누릅니다.
3. PC에서 설치합니다 (SideQuest, Meta Quest Developer Hub, 또는 adb):
   ```bash
   adb install -r QPBridge-Quest.apk
   ```
4. 퀘스트 **앱 보관함 → 오른쪽 위 필터 → "출처를 알 수 없음"** 에서 **QP브릿지 퀘스트** 를 실행합니다.

## 사용법

1. 퀘스트: **설정 → 기기(또는 블루투스) → 블루투스 켜기**. Wi-Fi는 꺼도 됩니다.
2. 휴대폰: 블루투스를 켜고 **QP브릿지 폰** 실행 → "근처 기기" 권한 허용 → **연결 대기 시작**.
   화면에 **연결 코드 4자리** 가 나옵니다.
3. 퀘스트: **QP브릿지 퀘스트** 실행 → 권한 허용 → **상대 기기 찾기** → 같은 코드의 버튼을 누릅니다.
4. "연결 완료" 가 뜨면 양쪽에서 메시지를 보낼 수 있습니다. **응답속도 테스트** 로 왕복 지연(ms)도 확인할 수 있습니다.

한 번 연결하면 퀘스트가 그 코드를 기억해서, 다음부터는 두 앱을 켜기만 하면 **자동으로 연결** 됩니다.
연결이 끊기면 최대 5번까지 자동으로 다시 연결을 시도합니다. ("연결 끊기"를 직접 누르면 자동 연결 기억이 지워집니다.)

## 문제 해결

| 증상 | 해결 |
|---|---|
| 퀘스트 목록에 아무것도 안 나옴 | 폰 화면이 "연결을 기다리는 중 · 코드 ____" 인지 확인. 두 기기를 1~2m 안에 두고 다시 찾기 |
| 폰에서 "BLE 광고를 지원하지 않음" | 일부 구형 폰은 광고(기다리는 쪽)를 못 합니다. **두 기기 모두** 에서 "역할 바꾸기"를 누르면 퀘스트가 기다리고 폰이 찾습니다 |
| "일시적 블루투스 오류(133)" 반복 | 양쪽 블루투스를 껐다 켜고 다시 시도 |
| 권한을 거부했음 | 설정 → 앱 → QP브릿지 → 권한 → "근처 기기" 허용 (Android 11 이하 휴대폰은 "위치") |

## 동작 방식 (개발자용)

- 폰은 서비스 UUID `7a3e0001-8c5b-4f1e-9d2a-51c0b7e4a9f3` 를 광고하고, 스캔 응답의 제조사 데이터(0xFFFF)에 `"QP"+4자리 코드` 를 담습니다.
- 퀘스트는 그 UUID로 필터링해 검색 → 연결 → MTU 517 요청 → 서비스 탐색 → TX 알림 구독.
- 특성: `…0002` RX (퀘스트→폰, Write), `…0003` TX (폰→퀘스트, Notify).
- 패킷 = `[플래그 1바이트][데이터]` (bit0 = 다음 패킷 이어짐). 메시지 = `[종류 1글자][UTF-8 본문]`, 최대 64KB.
  종류: `T` 텍스트, `H` 기기 이름, `P`/`O` 핑/퐁.
- 다른 기능(예: 폰을 VR 리모컨으로 쓰기, 센서 값 전송)을 붙이려면 `Proto` 에 메시지 종류를 추가하고
  `MainActivity.onMessage` 에서 처리하면 됩니다.

### 한계
- BLE는 텍스트·제어 신호용입니다. 영상이나 큰 파일 전송에는 느립니다 (보통 수십 KB/s).
- 앱을 완전히 닫으면 연결이 끊깁니다. (백그라운드 상주 서비스는 넣지 않았습니다.)
- 데이터는 BLE 연결 위에서 암호화 없이 오갑니다. 민감한 정보는 보내지 마세요.

## 빌드

```bash
# Android SDK(platform 34, build-tools 34) 필요. local.properties 에 sdk.dir 지정
keytool -genkeypair -keystore signing/qpbridge.jks -alias qpbridge -keyalg RSA -keysize 2048 \
        -validity 10000 -storepass qpbridge -keypass qpbridge -dname "CN=QPBridge"   # 처음 한 번
./gradlew assembleRelease
# → app/build/outputs/apk/quest/release/app-quest-release.apk
# → app/build/outputs/apk/phone/release/app-phone-release.apk
```

서명 키(`signing/qpbridge.jks`)는 저장소에 올리지 않습니다. 다른 키로 다시 빌드한 APK는
기존 앱 위에 덮어 설치할 수 없으니, 그때는 기존 앱을 지우고 설치하세요.
키가 없으면 디버그 키로 서명됩니다.
