# QP브릿지 — 휴대폰 화면을 메타퀘스트에서 보고 원격 조작

휴대폰(Android) 화면과 **소리**를 메타퀘스트로 보내고, 퀘스트 컨트롤러로 휴대폰을 **터치·스와이프·뒤로/홈·글자 입력** 하는 앱입니다.
**Wi-Fi가 꺼져 있어도 됩니다.** 인터넷·공유기 없이 두 가지 방법으로 연결합니다.

| 연결 방법 | Wi-Fi | 화질 (부드럽게 / 보통 / 선명하게) | 비고 |
|---|---|---|---|
| **USB-C 케이블** (추천) | 필요 없음 | 1280 / 1920 / 2560px · 30fps · 최대 4~14Mbps | 가장 선명하고 빠름 |
| **블루투스 고속** (자동) | 필요 없음 | 720 / 1080 / 1440px · 15~8fps · 최대 0.5~1.4Mbps | 블루투스 연결 후 자동으로 열림 (Android 10+) |
| **블루투스** (기본) | 필요 없음 | 640 / 960 / 1280px · 10~4fps · 최대 0.15~0.35Mbps | 고속이 안 될 때. 흐리고 느림 |

- 블루투스는 실제 속도를 재서 화질(비트레이트)을 자동으로 맞춥니다. '선명하게'는 해상도를 높이고 움직임(fps)을 줄여서 글자를 또렷하게 합니다.
- 두 기기가 모두 지원하면 **H.265** 로 보내서 같은 속도에서 더 선명합니다 (갤럭시 S2x·퀘스트 3 등). 아니면 H.264.
- **소리**: 휴대폰에서 재생되는 앱 소리(유튜브·음악·게임 등)를 퀘스트 스피커로 보냅니다. Android 10 이상, '녹음' 권한 필요(마이크는 쓰지 않음).

모두 동시에 켜 두고 USB → 블루투스 고속 → 블루투스 순서로 가장 빠른 것을 자동으로 씁니다.

| 파일 | 설치할 기기 |
|---|---|
| `release/QPBridge-Quest.apk` | 메타퀘스트 2 / Pro / 3 / 3S |
| `release/QPBridge-Phone.apk` | Android 8.0 이상 휴대폰 (iPhone 불가) |

## 설치

**휴대폰**: `QPBridge-Phone.apk` 를 열어 설치 ("출처를 알 수 없는 앱" 허용).

**메타퀘스트** (사이드로드):
1. 휴대폰 Meta Horizon 앱 → 기기 → 헤드셋 설정 → **개발자 모드 ON**
2. 퀘스트를 PC에 USB로 연결 → 헤드셋에서 "USB 디버깅 허용"
3. `adb install -r QPBridge-Quest.apk` (또는 SideQuest / Meta Quest Developer Hub)
4. 퀘스트 앱 보관함 → 필터 → **출처를 알 수 없음** → **QP브릿지 퀘스트**

## 처음 한 번 설정 (휴대폰)

1. **QP브릿지 폰** 실행 → "근처 기기"·알림 권한 허용. 처음 화면 공유를 시작할 때 **'녹음' 권한도 허용**하면 소리가 전달됩니다
2. **원격 조작 권한 켜기**: 앱의 "접근성 설정 열기" → 설치된 앱(서비스) → **QP브릿지 원격 조작** → 사용
   - 회색으로 막혀 있으면 (Android 13 이상, 직접 설치한 앱): 앱의 "앱 정보 열기" → 오른쪽 위 **⋮ → 제한된 설정 허용** → 다시 켜기
   - 이 권한이 없으면 화면 **보기만** 됩니다.

## 사용법

### USB-C 케이블 (추천)
1. 휴대폰에서 **QP브릿지 폰** 을 열고 **화면 공유 시작** → "전체 화면" 선택 → 시작
2. 퀘스트에서 **QP브릿지 퀘스트** 실행
3. USB-C ↔ USB-C 케이블로 두 기기를 연결
4. 뜨는 창에서 **허용/확인** 을 누릅니다 (USB 기기 사용 허용, "이 액세서리가 연결되면 열기")
5. 퀘스트 화면 왼쪽에 휴대폰 화면이 나옵니다.

> 연결이 안 되면: 휴대폰 알림창의 **USB 설정**에서 "USB 제어"를 **이 기기 ↔ 연결된 기기** 로 바꿔 보세요.
> 어느 쪽이 USB 호스트가 되든 동작하도록 만들었습니다. 케이블은 **데이터 전송이 되는** USB-C 케이블이어야 합니다 (충전 전용 X).

### 블루투스 (무선)
1. 두 기기 모두 블루투스 켜기 (퀘스트: 설정 → 기기 → 블루투스). Wi-Fi는 꺼도 됩니다.
2. 휴대폰: **화면 공유 시작** — 화면에 **연결 코드 4자리** 가 보입니다
3. 퀘스트: **블루투스로 휴대폰 찾기** → 같은 코드 선택
4. 다음부터는 앱만 켜면 자동으로 다시 연결됩니다.

### 퀘스트에서 조작
| 동작 | 방법 |
|---|---|
| 탭 | 휴대폰 화면을 가리키고 트리거 |
| 길게 누르기 | 트리거를 0.5초 이상 누르고 있기 |
| 스와이프·드래그 | 트리거를 누른 채 움직였다 떼기 (뗄 때 실행됨) |
| 스크롤 | 휴대폰 화면을 가리키고 엄지 스틱 위/아래 |
| 뒤로 / 홈 / 최근 앱 / 알림창 | 오른쪽 버튼 |
| 글자 입력 | 휴대폰의 입력칸을 먼저 탭 → 오른쪽 입력칸에 쓰고 **입력** (⌫ 로 한 글자 지우기) |
| 화질 | 부드럽게 / 보통 / 선명하게 |
| 소리 | 🔊 소리 켜짐/꺼짐 (끄면 휴대폰도 소리를 안 보내서 그만큼 영상이 선명해짐). 크기는 퀘스트 볼륨 버튼 |
| 크게 보기 | 영상 오른쪽 위 **◧ 크게 보기** → 조작판을 숨기고 화면을 크게. 퀘스트 창 모서리를 잡아 늘려도 됨 |

공유 중에는 휴대폰 화면이 꺼지지 않게(어둡게) 유지합니다. 휴대폰 알림의 **공유 중지** 로 끌 수 있습니다.

## 화면이 안 보일 때

퀘스트 앱 오른쪽 아래 **진단** 칸에 숫자가 나옵니다. 휴대폰 쪽 기록도 `[폰]` 으로 퀘스트 기록창에 함께 표시됩니다.

| 진단 내용 | 뜻 / 해결 |
|---|---|
| 영상 설정 0회, 받은 프레임 0 | 휴대폰이 영상을 안 보냄 → 휴대폰에서 **화면 공유 시작** 했는지 확인. `[폰]` 기록에 인코더 오류가 있는지 확인 |
| 받은 프레임은 늘어나는데 화면 표시 0 | 퀘스트 디코더 문제 → 앱이 자동으로 다른 디코더로 바꿔 봅니다 |
| 화면 표시도 늘어나는데 검은 화면 | 휴대폰에서 보고 있는 앱이 캡처를 막는 앱(은행, 넷플릭스 등)일 수 있음 |
| 휴대폰: 블루투스 1~3KB/s | 블루투스가 너무 느림 → 두 기기를 가까이 두거나 USB 케이블 사용 |

그래도 안 되면 진단 칸과 기록창 내용을 알려 주세요.

## 한계 / 주의

- 소리: 일부 앱(전화·통화 앱, 소리 캡처를 막은 앱)은 소리가 전달되지 않습니다. 휴대폰 스피커에서도 소리가 계속 나니 휴대폰 볼륨은 줄여 두세요 (전달되는 소리 크기에 영향을 줄 수 있으니 0으로는 말고 작게).
- 블루투스는 영상용으로는 느린 통로라, 움직이는 화면은 흐리고 끊길 수 있습니다. 가장 선명한 화면은 USB 케이블입니다.
- 스와이프는 손을 뗄 때 한 번에 실행됩니다 (실시간 드래그 아님).
- 은행·결제 앱, 넷플릭스 등 일부 앱은 화면 캡처를 막아 검은 화면으로 보입니다.
- 휴대폰 잠금 화면의 PIN/패턴 입력은 보안상 원격으로 안 될 수 있습니다. 공유 전에 잠금을 풀어 두세요.
- 데이터는 암호화하지 않습니다. 두 기기 사이(케이블/블루투스 10m 이내)에서만 오가지만, 블루투스는 근처의 다른 사람이 연결을 시도할 수 있으니 코드를 꼭 확인하세요.
- 실제 퀘스트·휴대폰에서 아직 시험하지 못했습니다. 문제가 있으면 앱 아래쪽 기록(로그)을 알려 주세요.

## 구조 (개발자용)

```
app/src/main   공통: Proto(프로토콜), Link/BleLink/BleCentralLink/BlePeripheralLink(블루투스 GATT),
               StreamLink(블루투스 고속 L2CAP), UsbLink(USB 액세서리), FrameParser, MessageQueue/Outbox(급한 것 먼저),
               Hub(연결 선택·관리)
app/src/phone  PhoneActivity, MirrorService(MediaProjection → H.265/H.264), AudioCapture(앱 소리 → AAC),
               RemoteControlService(접근성 제스처), PhoneController(명령 처리)
app/src/quest  ViewerActivity(조작판·터치 변환), VideoDecoder(→ TextureView), AudioPlayer(AAC → 스피커), AspectFrame
```

- 메시지: `[종류 1바이트][내용]`. 블루투스는 MTU에 맞춰 `[플래그][데이터]` 패킷으로 나누고, USB는 `[종류][길이 4바이트][내용]` 스트림.
- 영상: `VIDEO_CONFIG(폭, 높이, SPS/PPS)` + `VIDEO_FRAME(키프레임 플래그, H.264)`. 전송이 밀리면 휴대폰이 키프레임까지 프레임을 버려 지연이 쌓이지 않게 합니다.
- 조작: `GESTURE(지속시간, 0~65535 정규화 좌표들)`, `GLOBAL(뒤로/홈…)`, `TEXT`, `BACKSPACE`.
- 블루투스: 휴대폰이 광고 + GATT 서버(영상은 Notify, 패킷 ≤512바이트), 퀘스트가 검색 + 클라이언트. MTU 517, 2M PHY.
  연결되면 퀘스트가 PSM 특성을 읽어 L2CAP 연결 지향 채널(고속)을 추가로 엽니다. 실패하면 GATT 로 계속.
- 소리·조작·상태 메시지는 영상보다 먼저 보냅니다 (영상 메시지 사이에 끼워 넣음).
- 퀘스트는 연결 직후 CAPS(H.265 지원 여부)를 보내고, 휴대폰은 지원하면 H.265 인코더를 먼저 씁니다.
- USB: 호스트가 된 쪽이 상대를 AOA(Android Open Accessory) 모드로 전환(제조사 `Shwo`, 모델 `QPBridge`)하고 벌크 전송.

## 빌드

```bash
# Android SDK(platform 34, build-tools 34) 필요, local.properties 에 sdk.dir 지정
keytool -genkeypair -keystore signing/qpbridge.jks -alias qpbridge -keyalg RSA -keysize 2048 \
        -validity 10000 -storepass qpbridge -keypass qpbridge -dname "CN=QPBridge"   # 처음 한 번
./gradlew assembleRelease
```

서명 키(`signing/qpbridge.jks`)는 저장소에 올리지 않습니다. 다른 키로 빌드한 APK는 기존 앱 위에 덮어 설치할 수 없으니,
그때는 기존 앱을 지우고 설치하세요.
